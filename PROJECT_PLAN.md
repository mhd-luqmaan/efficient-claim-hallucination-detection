# Project Plan: Efficient Claim-Level Hallucination Detection in Large Language Models Using Semantic and Linguistic Features

## 1. Executive Summary & Research Question
Can a lightweight hybrid NLP model combining compact semantic embeddings and interpretable linguistic features detect hallucinated claims effectively in LLM answers, while requiring orders of magnitude less computation and latency than deploying a large 7B+ LLM as a judge?

This system addresses claim-level hallucination detection on consumer hardware (GTX 1650 4GB VRAM & CPU fallback) without requiring external LLM API calls or heavy RAG setups.

---

## 2. Hardware Profile & Feasibility
- **GPU**: NVIDIA GeForce GTX 1650 (4096 MiB VRAM, Compute 7.5, Driver 592.00, CUDA capable)
- **CPU**: Intel/AMD x86_64 host running Windows 11
- **Python**: 3.9.0
- **Embedding Model**: `all-MiniLM-L6-v2` (22.7M parameters, ~80 MB footprint, 384-d vector output)
- **Feasibility Assessment**:
  - SentenceTransformer `all-MiniLM-L6-v2` easily fits into GPU VRAM (< 200 MB loaded) or CPU RAM.
  - Sentence embeddings and feature extraction take ~5–10 ms per claim on CPU and ~1–2 ms on GPU.
  - Tabular classifiers (Random Forest, XGBoost) require minimal memory (< 100 MB) and execute sub-millisecond inference per claim.

## 4. Architectural Design & Feature Engineering

### 4.1 Claim Extraction Pipeline
1. Sentence segmentation using spaCy (`en_core_web_sm`).
2. Edge-case sanitization (filtering empty tokens, punctuation-only fragments).
3. Structured output: `response_id`, `claim_id`, `claim_text`.

### 4.2 Semantic Features (Compact Transformer: all-MiniLM-L6-v2)
- `question_claim_similarity`: Cosine similarity between claim embedding and question embedding.
- `question_claim_semantic_distance`: $1 - \text{cosine\_sim}$.
- `claim_answer_similarity`: Cosine similarity between claim and overall answer embedding.
- `context_claim_similarity`: Cosine similarity between claim and reference context (if provided, default 0 when omitted).
- Fast in-memory LRU cache for question and answer embeddings to avoid duplicate encodings.

### 4.3 Linguistic Features (spaCy NLP)
- **Surface**: character count, word count, average token length, sentence length.
- **Named Entities**: counts of PERSON, ORG, GPE, LOC, DATE, CARDINAL, MONEY, PERCENT.
- **Numerical Patterns**: regex/NER detection of years, dates, quantities, monetary values.
- **Part-of-Speech**: counts and ratios of NOUN, VERB, ADJ, ADV, PRON.
- **Epistemic Certainty / Uncertainty Markers**:
  - Certainty lexicon: *definitely, certainly, clearly, undeniable, absolutely, truly, proven*.
  - Uncertainty lexicon: *probably, possibly, maybe, likely, reportedly, approximately, alleged, seems*.

### 4.4 Feature Fusion & Classification
1. Standardized feature vector concatenating semantic metrics and linguistic statistics.
2. Baselines and Hybrid Models:
   - **Experiment A (Linguistic Baseline)**: Linguistic features -> Random Forest.
   - **Experiment B (Semantic Baseline)**: MiniLM embeddings + similarity metrics -> Logistic Regression & Random Forest.
   - **Experiment C (Proposed Hybrid)**: Semantic features + Linguistic features -> Random Forest & XGBoost.

## 5. Phased Roadmap
- [x] **Phase 1: Environment & Setup**
  - Verify Python 3.9, GPU GTX 1650 (4GB), CUDA, and disk space.
  - Test and verify `all-MiniLM-L6-v2` loading and embedding inference.
  - Setup directory structure, `.gitignore`, `configs/config.yaml`, `requirements.txt`.
- [ ] **Phase 2: Dataset Preparation & Preprocessing**
  - Download HaluEval QA dataset.
  - Segment answers into claims, map labels (0 = Supported, 1 = Hallucinated).
  - Create stratified splits: 70% Train, 15% Validation, 15% Test.
  - Save structured datasets in `data/processed/`.
- [ ] **Phase 3: Feature Engineering Pipeline**
  - Implement `claim_extraction.py`, `semantic_features.py`, `linguistic_features.py`.
  - Implement `feature_fusion.py` with caching and optional context support.
  - Generate and persist feature matrix for train/val/test splits.
- [ ] **Phase 4: Baselines & Model Training**
  - Train Experiment A: Linguistic-only model.
  - Train Experiment B: Semantic-only model.
  - Train Experiment C: Hybrid models (Random Forest, XGBoost).
  - Implement probability calibration (Platt scaling / Isotonic regression) to output reliable Hallucination Risk Scores.
- [ ] **Phase 5: Evaluation & Ablation Study**
  - Compute Accuracy, Precision, Recall, F1, ROC-AUC, Confusion Matrix.
  - Measure inference latency (claims/sec), memory footprint, model size.
  - Conduct feature group ablation (Linguistic only, Semantic only, without NER, without Certainty).
  - Export experiment comparison tables and visualization charts in `results/`.
- [ ] **Phase 6: Predictor & Streamlit Application**
  - Build `predict.py` with multi-claim risk aggregation (mean risk, max risk, high-risk ratio).
  - Implement feature importance/signal explanation for each claim.
  - Develop interactive Streamlit UI (`app/streamlit_app.py`) with clean typography, progress indicators, demo presets, and risk breakdowns.
- [ ] **Phase 7: Unit Testing, Documentation & Final Verification**
  - Write test suite covering edge cases (empty text, single claim, multi-sentence, numbers/dates).
  - Write comprehensive `README.md` and walkthrough.
